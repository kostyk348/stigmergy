# stigmergy — работа как след в среде, а не как карточка в доске

Координация без доски, без очереди, без владельца и без диспетчера.

```bash
stig need   --env DIR --capability rust --object "разобрать RFC 791"
stig status --env DIR
stig work   --env DIR --capability rust --as worker-1 --do "make"
stig demo
```

## Что здесь вместо доски

Среда — каталог `traces/`. Работа существует как **потребность** с силой; сила убывает:

```
сила(t) = strength * exp(-decay * (t - made))
```

Это и есть весь приоритет — другого нет. Ни колонок, ни статусов, ни assignee.

| В доске | Здесь |
|---|---|
| карточка ждёт в колонке | потребность имеет силу и гаснет сама |
| приоритет ставит человек | приоритет = сила следа, её нельзя «выставить» |
| владелец закреплён | никто не закреплён: притягивает способность |
| брошенная карточка висит годами | брошенная потребность испаряется по распаду |
| аренду снимает сторож/диагностика | след «занято» живёт две минуты и исчезает сам |
| никто не узнаёт, что работу некому делать | потребность гаснет молча — это видно в аудите |

## Правила (проверены тестами)

1. `need` притягивает только ту способность, которая в нём указана.
2. Взял работу — оставил `claim`; он гасит притяжение для остальных и **испаряется за ~2 минуты**. Процесс умер — работа освободилась без уборщика.
3. Не вышло — оставил `warn`; он **отталкивает** других ~25 минут и тоже испаряется. Никто не повторяет чужую ошибку мгновенно, но и запрет не вечен.
4. Сделал — потребность удаляется, остаётся `done` как след работы для аудита (живёт ~сутки).
5. Никто не взял — потребность гаснет. **Молча.** Это цена схемы, см. README ниже.

## Проверка

```bash
$ cargo test
test result: ok. 8 passed; 0 failed       # 7 в env.rs + 1 в CLI-тестах
$ cargo run -q -- demo
итог: 8 проверок, 0 провалов
```

Живой прогон CLI (три дела, два исполнителя, один провал, сутки спустя):

```
worker-1: притянуло «разобрать RFC 791» (сила 1.00)
worker-1: не вышло (код 7); предупреждение оттолкнёт других
worker-2: ничего не притягивает (способность rust)      ← warn блокирует
worker-3: притянуло «прочесать музей» (сила 1.00)
worker-3: сделано, след работы оставлен
через сутки в среде осталось: done python 0.11          ← needs испарились, работа осталась в аудите
```


## Три слоя сверх следов

**Лад** (русский консенсус, `src/consent.rs`) — решение идёт, если против него никто не
возразил. Воздержания нет: кто промолчал до срока, тот согласился и в ответе. Возражение
требует причины и снимается **в кругу, где не перебивают**, — а не голосуется.

```bash
stig lad open --env D --id reliz --text "делать ли релиз" --members "анна,борис,вера"
stig lad say  --env D --id reliz --who борис --verb возражение --reason "нет тестов"
stig lad show --env D --id reliz
```

**Метр** (Киберфольк Бира, `src/dial.rs`) — человек сам ставит стрелку 0..100, прибор не
задаёт вопросов. Берётся худшее показание (боль не усредняют), и оно стареет: за полсуток
без подтверждения возвращается к нулю.

```bash
stig dial --env D --who анна --value 75 --note "не то делаем"
stig dials --env D
```

**ЧЕКО** (`src/checo.rs`) — симулятор «что если»: прогоняет план по среде и показывает,
что успеет, а что умрёт молча.

```bash
stig checo --env D --worker rust:1:600 --horizon 86400
```

Итог: **22 теста**, демо **16 проверок, 0 провалов**. Формат работы, собранный из этих
блоков, — [Череда](https://github.com/kostyk348/chereda).

## Провенанс

Идея не выдумана: Пьер-Поль Грассе описал стигмергию в 1959 году на термитах;
архитектура «доски» Hearsay-II (CMU, 1971–1976) довела её до софта, но оставила
управляющий слой. Здесь управляющего слоя нет вовсе. Русская линия — сводные отряды
Макаренко (1923) и «трудовые установки» Гастева: работа как движение, а не как состояние.
Подробности и цитаты — `docs/PARADIGMS.md`.

## Чего это не даёт

- **Нет обзора.** Никто не знает целого: у среды нет «экрана». Для этого нужен отдельный наблюдатель (у нас это `homeostat`).
- **Молчаливая смерть.** Потребность без исполнителя исчезает, и никто не получает сигнала — в отличие от алгедОники Бира. Это лечится часами восстановления, но тогда появляется центр.
- **Гонки.** Двое могут взять один след в одну секунду: `claim` сужает окно, но не закрывает. В тестах этого не видно, в жизни будет.
- **Настройка распада.** Неверная скорость либо морит работу голодом, либо спамит.
